# Методологія UTP v0.3

## Дослідницькі питання

1. Наскільки український переклад того самого змісту потребує більше токенів в одному публічному токенізаторі?
2. Чи є контрольоване скорочення токенів від змін пропорції UA/EN при незмінному словнику та обсязі навчання?
3. Чи можна отримати покращення UA без понад 10% погіршення EN на dev (поріг для пілоту зафіксований до аналізу test)?

## Розподіл

- Завантажити UD Ukrainian-IU та UD English-EWT за відповідними ліцензіями, зберегти SHA-256.
- Об'єднати офіційні три вихідні файли для кожної мови, адже той самий документ може бути розділений між офіційними наборами.
- Новий train/dev/test визначити по хешу `seed:document_id`, орієнтовно 80/10/10 за **кількістю документів**, а не речень; частки документів можуть відхилятися через хешування.
- Речення з невідомим ID документа до першого маркера вилучити і порахувати.
- Точні нормалізовані дублікати речень між різними підвибірками вилучити з усіх наборів, повтори в межах набору також прибрати; оцінити статистику вилучення.
- Це не виявляє перефразування, схожих абзаців, авторського або тематичного витоку; для великої публікації потрібні додаткові методи та ручна перевірка.

## Навчання і вибір

- Порівнюються SentencePiece BPE з `byte_fallback=True`, фіксованим `vocab_size`, однаковими параметрами нормалізації та приблизно однаковим байтовим бюджетом.
- Пропорції UA: 25/50/75/100%. 50% — baseline.
- Суміші оцінюються на **dev**. Обирається найменша кількість українських токенів серед моделей із UA share ≥ 50%, якщо англійських токенів не більше 110% baseline. У разі відсутності альтернативи обирається baseline.
- Рішення фіксується у `decision.json`; це запобігає підбору моделі на test.
- Суворий test оцінюється тільки після фіксації. Виконання `final_evaluation.py` повторно в тій самій директорії блокується, щоб зменшити ризик непомітних підборів.

## Показники

- Загальна кількість токенів на *тих самих* українських тестових реченнях.
- Загальна кількість англійських токенів на їхньому незалежному корпусі для оцінки втрат EN.
- `tokens/word`, `bytes/token`, точне відновлення оригінального Unicode.
- Відносна зміна `100 × (1 - N_candidate / N_baseline)`; додатне значення — менше токенів.
- 95% довірчий інтервал методом paired cluster bootstrap з повторним вибором цілих документів, а не речень (за переданими ID груп).
- Паралельний UA/EN бенчмарк використовує вирівняні переклади; `UA/EN ratio` >1 означає більше токенів українською у визначеній вибірці. Без паралельних даних така інтерпретація неприпустима.

## Обмеження

- Обсяг UD малий і домени обмежені; одне seed/словник недостатнє для стійких висновків.
- Наявність опублікованих навчальних корпусів може створювати схожість із заздалегідь навченими іншими моделями, якщо виконуються зовнішні порівняння.
- Порівняння SentencePiece 1024 та `tiktoken` з великим словником — **не** контрольований тест методів.
- Для перенесення в LLM потрібне узгоджене оновлення вхідних/вихідних embedding, додаткове навчання, метрики якості, латентності, реальної GPU-вартості та безпеки.
