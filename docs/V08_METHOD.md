# UTP v0.8 — збільшення словника без заміни наявних токенів

**Робоча гіпотеза:** можна зменшити українські токени, додаючи вибрані кириличні фрагменти до існуючого токенізатора SmolLM2, не видаляючи оригінальні токени та не змінюючи їхні ID. Це може знизити регресію англійської, що виникала в v0.6–v0.7 після повної заміни словника.

## Фіксований інженерний експеримент

- Модель: HuggingFaceTB/SmolLM2-135M, checkpoint `93efa2f097d58c2a74874c7e644dbc9b0cee75a2` (Apache 2.0).
- Дані: **Tatoeba CC0** для української та англійської. 75/25 розділення за SHA-256 речення, навчальні речення не використовуються в оцінці. Це вже знайоме нам джерело, **не** новий незалежний benchmark.
- Вибір токенів: 128 найвагоміших кириличних фрагментів довжиною 4–10 символів, частота не менш як 3 в **UA TRAIN**. Не використовувати тест для відбору шматків. Тільки Unicode-кирилиця, без латиниці.
- **Старі ID повністю незмінні.** Додатково перевірити, що токенізація речень без кирилиці англійською побітово не змінюється; заборонити непомітну нормалізацію чи втрату Unicode.
- Нові embeddings ініціалізувати середнім векторів вихідної токенізації відповідних фрагментів. Розмір старих embeddings перевірити до й після `resize_token_embeddings`.
- При оптимізації дозволити змінювати **лише нові рядки** вхідної та вихідної embedding-таблиць. Попередньо навчену модель, вихідні ID та старі embedding-рядки зберегти.
- Контрольований двомовний навчальний розклад: 3 UA : 1 EN приклад, seed 42; контрольні етапи: **0, 64, 256** кроків.
- Оцінювати на **однакових 30 UA та 30 EN реченнях**, вибраних за спільним фільтром довжини **до** аналізу якості. Фіксувати SHA-256 тестових речень, реальну кількість токенів і негативну логарифмічну правдоподібність **біт/оригінальний UTF-8 байт**.
- Публікувати лише агреговані вимірювання, контрольні суми та методику: без речень, даних корпусу, нових token-поверхонь та ваг моделі.

## Критерії

Ми не припускаємо наперед, що зміна зменшить токени: якщо на 30 UA реченнях додані токени не використовуються, це має бути чесно зафіксовано. Результат по англійській оцінюється не лише за незмінними ID, а й за **softmax**: додаткові вихідні класи здатні погіршити модель навіть без зміни оригінальних входів.

Зниження токенів не є автоматичним зниженням вартості ChatGPT. Подальша перевірка має проводитися на іншому, по-справжньому незалежному українському корпусі з авторсько-документним контролем, а потім у задачах генерації та розуміння тексту.

## Запуск

Весь сценарій — [additive_vocab.py](../additive_vocab.py), автоматичний запуск — [additive_vocab.yml](../.github/workflows/additive_vocab.yml). Потрібні Python 3.12, CPU PyTorch 2.6.0, Transformers 4.52.4 і залежності проєкту.

```bash
python -m pytest -q
python additive_vocab.py --new-tokens 128 --samples 30 --seed 42 --out results/additive_v08.json
```

GitHub Actions автоматично завантажує CC0, проводить тест та публікує лише агрегований звіт.
